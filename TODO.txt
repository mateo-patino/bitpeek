Here's a list of features that will likely improve `bitpeek` that have not been
implemented yet:

1. Shell-friendly option: Add an option (e.g. -s for Shell) that prints output
in a format that can be easily consumed by shell scripts. A one-line, space-
separated format could work; other shell-friendly formats exist.

2. Arbitrary base option: Add an option (e.g. -n) that prints output in an 
arbitrary base requested by the user. `bitpeek` uses the strtoul interface,
which can only handle bases between 0 and 36, so a `bitpeek`-specific base
converter will need to be implemented.

3. Endianness: Add some way to visualize an integer written in little- and
big-endian. It should easy to see how the byte order is reversed. The 
different byte orderings can likely be printed in any base using the mappings
8 bits = 6 octal digits = 2 hex digits = 1 byte, though this would likely require
overwriting any grouping options the user passed.
